## In scope
### 1. Scaffold
- Next.js (latest stable, App Router, React Server Components), strict TypeScript, pnpm.
- Tailwind + shadcn/ui (defaults only, no theme edits), lucide icons (shadcn default).
- next-intl with `/en/...` and `/es/...`; every string in `messages/en.json` and `messages/es.json`

- ESLint (Next + TypeScript strict rules) with two project rules: no decimal number literals and no

- Vitest (unit + integration), Playwright (uses the machine's preinstalled Chromium).
- Scripts: `dev`, `build`, `lint`, `typecheck`, `test`, `test:goldens`, `test:e2e`, `db:migrate`,
  `db:seed-demo`, `demo:reset`, `demo:samples`. CLAUDE.md "Commands" filled in.

### 2. Database (local Postgres 16 already on this machine)
- `scripts/dev-db.sh start|stop|reset` runs a private Postgres in `.pgdata/` (ignored by git); the
  session-start hook calls it, so a fresh cloud machine is ready automatically.
- Drizzle schema + migrations. Every tenant table has `agency_id`; Postgres row-level security
  policies restrict every query to the current agency; an integration test proves agency A can never
  read agency B's rows (SPEC §21).
- Tables in this slice (minimal columns, the rest arrive with their slices): agency, branch, user,
  client, worksite, client_billing_profile (overtime billing rule only), worker (no SSN yet — slice
  k), worker_alias (nickname map), job_order, rate_card (effective dates, pay rate, bill rate, OT
  multiplier as a fraction), assignment, source_document, time_entry (all provenance + pass A/B +
  confidence + status), pay_run, pay_line, bill_line, invoice, export (format, mapping version, file
  hash, control totals), audit_event (append-only, enforced by a database trigger that rejects
  UPDATE/DELETE), and rule tables: `overtime_rule` and `extraction_setting`, both effective-dated.

### 3. Demo agency and sample documents (fictional, generated by code)
- One invented agency, three clients: California, Illinois, Massachusetts; worksites with state,
  county, city; 40 invented workers (including accented names, compound surnames and nicknames, to
  exercise matching), job orders, rate cards, assignments; two weekly pay periods.
- Sample documents generated by a script and committed under `demo/samples/`:
  handwritten-style sign-in sheets (rendered in a handwriting-style open-licence font, then rotated,
  blurred, given noise and phone-photo artefacts; one saved as HEIC), a client-signed PDF, a

  proposed extraction goldens.
- `demo:reset` restores everything in one step; the same reset sits behind the banner button.
- Demo mode makes **no external calls**: the document reader replays recorded answers (see 4).

### 4. Reading timesheets (intake + extraction)
- Accepted in this slice: JPG, PNG, HEIC, PDF, time-clock CSV/XLSX, and VMS exports through saved
  column-mapping profiles (Fieldglass profile first; Beeline, Coupa, Magnit are data rows later).
- Files go to a document store (local folder in dev/demo; cloud storage at deploy — decision record).
  Each document is hashed; duplicates are detected.
- **Redaction before any model call:** local OCR (runs on our server, no external call) finds
  SSN-shaped and date-of-birth text and blacks it out on the image copy that is sent to the model.
  A test image with a printed fake 9xx SSN proves it. Known limit: handwritten numbers may evade OCR,
  so the model output is also filtered and anything SSN-shaped is dropped, never stored or logged.
- **Two independent passes** with different prompts and different image versions (A: original
  orientation; B: straightened, contrast-enhanced, split into overlapping halves). Each pass returns
  structured JSON (worker name as written, date, in, out, breaks, total, and a box on the page for
  every value). Model: Claude Opus 5.5 (`claude-opus-5-5`), structured output validated against a
  schema, with Anthropic's automatic fallback model turned on for the rare case a request is
  declined.
- **Confidence per cell** = passes agree (value and roughly the same box) + validators pass (date
  in period, in before out, ≤ 24 h per day, worker on roster, assignment active that day) +
  arithmetic checks (row totals and column totals add up). Anything else → `needs_review`. A
  handwritten value below the threshold (stored in `extraction_setting`) is never auto-accepted.
- CSV/XLSX/VMS files are parsed deterministically (no model), still validated the same way.
- **Name matching:** accent folding, compound surnames, per-agency nickname map; never creates a
  worker — unmatched names are flagged.
- **Same code path in demo and production:** the model is called through one interface with two
  transports — the real API, and a replay of recorded answers keyed by a hash of the exact request.
  Demo mode and tests use the replay. The recordings are made once by running the real API on the
  generated samples (needs the API key, decision D5) and committed; they contain fictional data only.
- Extraction golden runner: scores field accuracy and "silent errors" (wrong value with high
  confidence) — silent errors must be 0. Cases are proposed in `tests/goldens/_proposed/extract/`.

### 5. Pay and bill computation (first piece of the rules engine)
- `packages/rules`: a pure package — no database, no files, no network, integer math only (lint
  rule enforces it). One file per rule with its legal citation.
- This slice implements: classify minutes per worker-week → straight pay → **federal weekly overtime
  over 40 hours** (29 U.S.C. § 207(a)(1); 29 C.F.R. Part 778), threshold and multiplier read from
  the effective-dated `overtime_rule` table, with a single pay rate per worker-week. That covers the
  Illinois and Massachusetts clients for ordinary weeks.
- **California entries are blocked** in this slice with a plain reason ("California daily and
  seventh-day overtime arrive with the full rules engine in slice (c)"), because paying them on
  weekly rules alone would be wrong. The same block applies to any jurisdiction without rules
  ("unknown jurisdiction blocks the run", SPEC §9).
- Bill lines: bill rate per minute; overtime billed per the client's billing rule (multiplier /
  straight time / not billable).
- Money in integer cents, time in integer minutes; one rounding, at line level, half-up; every
  line has an explain string, e.g. `OT: 37 min × $27.375/h (1.5 × $18.25) = 1688.125¢ → rounded
  half-up once to $16.88`.
- Second-opinion subagent reviews the rule code and its golden cases before I call it done.
- Proposed rules goldens: 38 h straight; 44 h with 4 h overtime; 40 h exactly; odd-cent rate where
  1.5× produces half cents (shows the rounding); client billing variants (multiplier / straight /
  not billable).

### 6. The converter page (`/convert`, pattern `convert.md`)
- Period tile → Step 1 Upload → Step 2 Review hours → Step 3 Review totals → Step 4 Export and
  invoices, exactly as the pattern file describes once the owner settles its open questions.
- Review grid (pattern `review.md`): filters, inline edit with a required reason, full keyboard
  navigation, side panel with the source image and the cell's box highlighted, bulk approve limited
  to high-confidence rows, every edit audited.
- Step 3 lists blockers (unmatched entries, no active assignment, missing rate, unknown or
  not-yet-supported jurisdiction, zero or negative pay, missing payroll file number) and the totals.
- Step 4 produces:
  - **Payroll CSV — Gusto hours import** (SPEC §13 format). A research subagent establishes Gusto's
    template columns and a second subagent checks them; if Gusto's template cannot be verified
    publicly I will ask the owner for one file: a blank hours template downloaded from Gusto.
    Earning-code map per agency (REG, OT, …). The export declares the earning types it carries and
    fails on any other. Control totals (workers, minutes by type, gross cents) must reconcile
    exactly to the pay lines, or the export fails. Byte-exact golden proposed in
    `tests/goldens/_proposed/exports/`.
  - **One invoice PDF** for the chosen client (pattern `_documents/invoice.md`), lines from the
    reviewed hours, totals equal to the bill lines.
- Demo banner on every page (pattern `_layouts/root.md`) with the reset control.
- Empty states follow `_components/empty-state.md`.

## Risks I am watching

  cannot, more cells go to review rather than being guessed.
- Model coordinates for boxes can be approximate; boxes are checked between passes, and a box that
  disagrees sends the cell to review.
- Gusto's help center blocks automated reading; the template columns may need the owner's file.
- Cost of real extraction: two Opus passes per page; I will measure the real cost per page on the
  samples and report it before any real use.
